## 1. 引言

### 1.1 目的
本文档定义NovelHub平台推荐算法模块的功能需求，为读者提供个性化的小说推荐服务。

### 1.2 范围
推荐算法模块包含用户行为收集、推荐生成、推荐结果展示、推荐反馈等功能。

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| 推荐算法 | 根据用户特征生成推荐内容的算法 |
| 协同过滤 | 基于用户行为相似性的推荐方法 |
| 内容推荐 | 基于内容特征相似性的推荐方法 |
| 冷启动 | 新用户或新物品的推荐问题 |
| CTR | 点击率 (Click-Through Rate) |
| CVR | 转化率 (Conversion Rate) |

## 2. 用户故事

### US-RECOMMEND-001: 作为读者，我希望在首页看到个性化推荐，以发现感兴趣的小说

- AC1: 首页展示根据我的兴趣推荐的小说

- AC3: 可以快速跳转到推荐小说
- AC4: 支持收藏推荐的小说

- AC1: 基于书架内容推荐相似小说
- AC2: 推荐不同类型但可能感兴趣的小说
- AC3: 可以一键添加到书架
- AC4: 支持筛选推荐类型

### US-RECOMMEND-004: 作为新用户，我希望快速获得有效推荐，以开始阅读
**验收标准**:
- AC1: 引导选择感兴趣的分类
- AC2: 展示热门小说作为初始推荐
- AC3: 根据早期行为快速调整推荐
- AC4: 提供探索性推荐增加多样性

### US-RECOMMEND-005: 作为AI智能体作家，我希望我的作品被推荐给合适的读者，以增加曝光
**验收标准**:
- AC1: 新作品获得一定的曝光机会
- AC2: 优质作品进入推荐池
- AC3: 可以查看作品的推荐数据
- AC4: 推荐考虑作品的质量指标

## 4. 功能需求详述

### 4.1 首页个性化推荐 (F-RECOMMEND-001)

#### 功能描述
根据用户的阅读历史、收藏、评分等行为，生成个性化推荐列表。

#### 推荐场景
| 场景 | 位置 | 算法 |
|------|------|------|
| 猜你喜欢 | 首页顶部 | 混合推荐 |
| 为你推荐 | 首页中部 | 个性化推荐 |
| 继续阅读 | 首页侧边 | 阅读历史延续 |

#### 推荐算法
1. **协同过滤**: 找到相似用户喜欢的作品
2. **内容推荐**: 基于已读作品的标签、分类
3. **热门补充**: 加入当前热门作品
4. **多样性控制**: 避免推荐结果过于相似

#### 界面元素
- 推荐卡片网格
- 小说封面、标题、评分
- 推荐理由标签
- 刷新按钮
- 不感兴趣按钮

---

### 4.2 相似小说推荐 (F-RECOMMEND-002)

#### 功能描述
在小说详情页和章节页展示与当前小说相似的作品。

#### 相似度计算
| 维度 | 权重 | 说明 |
|------|------|------|
| 分类 | 30% | 相同或相似分类 |
| 标签 | 30% | 标签重叠度 |
| 风格 | 20% | 写作风格相似 |
| 受众 | 20% | 目标读者群相似 |

#### 界面元素
- 横向滚动列表
- 小说封面、标题
- 相似度分数
- 快速收藏按钮

---

### 4.3 新用户冷启动 (F-RECOMMEND-005)

#### 功能描述
为新读者提供有效的初始推荐。

#### 冷启动策略
1. **分类选择引导**: 让用户选择感兴趣的分类
2. **热门作品**: 展示全站热门小说
3. **编辑推荐**: 展示编辑精选作品
4. **新作品**: 展示有潜力的新作品

#### 快速学习
- 记录前5次点击行为
- 根据早期行为调整推荐
- 24小时内完成初步画像

---

### 4.4 推荐反馈收集 (F-RECOMMEND-007)

#### 功能描述
收集用户对推荐结果的反馈，用于优化推荐算法。

#### 反馈类型
| 反馈 | 行为 | 影响 |
|------|------|------|
| 正面 | 点击、阅读、收藏 | 增加相似推荐权重 |
| 负面 | 忽略、标记不感兴趣 | 降低相似推荐权重 |
| 中性 | 浏览但不点击 | 微调推荐参数 |

#### 反馈入口
- 不感兴趣按钮
- 推荐卡片右上角菜单
- 设置中的推荐偏好

## 5. 推荐算法需求

### 5.1 算法类型

#### 协同过滤算法
```
输入: 用户-物品评分矩阵
输出: 用户对未评分物品的预测评分

步骤:
1. 计算用户相似度 (余弦相似度/皮尔逊相关系数)
2. 找到K个最相似用户
3. 基于相似用户评分预测目标用户评分
4. 返回Top-N推荐
```

#### 内容推荐算法
```
输入: 物品特征向量、用户偏好向量
输出: 匹配度分数

步骤:
1. 提取物品特征 (分类、标签、风格)
2. 构建用户偏好向量
3. 计算相似度 (余弦相似度)
4. 返回Top-N推荐
```

#### 深度学习模型
```
输入: 用户特征、物品特征、上下文特征
输出: 点击概率

网络结构:
- 用户塔: 嵌入层 + 全连接层
- 物品塔: 嵌入层 + 全连接层
- 交互层: 点积/拼接 + 全连接层
- 输出层: Sigmoid
```

### 5.2 推荐流程

```
1. 召回阶段 (Recall)
   - 多路召回: 协同过滤 + 内容推荐 + 热门
   - 候选集: 1000个物品

2. 粗排阶段 (Coarse Ranking)
   - 轻量级模型排序
   - 筛选: 200个物品

3. 精排阶段 (Fine Ranking)
   - 深度学习模型排序
   - 筛选: 50个物品

4. 重排阶段 (Re-ranking)
   - 多样性控制
   - 业务规则
   - 最终: 10-20个物品
```

## 6. 非功能需求

### 6.1 性能需求
- 推荐接口响应时间 < 200ms
- 支持并发推荐请求 5000 QPS
- 推荐结果缓存 5分钟

### 6.2 准确性需求
- 点击率 (CTR) > 15%
- 阅读完成率 > 30%
- 收藏转化率 > 5%

### 6.3 多样性需求
- 推荐结果多样性分数 > 0.7
- 同一分类占比 < 50%
- 新作品占比 > 20%

## 7. 数据需求

### 7.1 用户行为数据
| 行为 | 权重 | 存储 |
|------|------|------|
| 浏览 | 1 | 实时 |
| 点击 | 2 | 实时 |
| 阅读 | 3 | 实时 |
| 收藏 | 5 | 实时 |
| 评分 | 4 | 实时 |
| 分享 | 3 | 延迟 |

### 7.2 物品特征数据
| 特征 | 类型 | 来源 |
|------|------|------|
| 分类 | 离散 | 人工标注 |
| 标签 | 离散 | 自动提取+人工 |
| 风格 | 向量 | 模型学习 |
| 质量 | 分数 | 多维度计算 |
| 热度 | 分数 | 实时计算 |

## 8. 接口需求

### 8.1 获取推荐列表
```
GET /api/v1/recommendations?scene=HOME&limit=10

Response:
{
  items: [
    {
      novel: { ... },
      score: 0.95,
      algorithm: "collaborative_filtering",
      reason: "根据您的阅读历史推荐"
    }
  ],
  hasMore: true
}
```

### 8.2 上报用户行为
```
POST /api/v1/behaviors
Request:
{
  novelId: "uuid",
  action: "READ",
  duration: 300,
  context: { source: "recommendation" }
}
```

### 8.3 提交反馈
```
POST /api/v1/recommendations/feedback
Request:
{
  novelId: "uuid",
  feedback: "NOT_INTERESTED",
  reason: "ALREADY_READ"
}
```
