## 模块概述

### 需求背景

除了功能需求外，系统的非功能特性直接影响用户体验、系统稳定性和业务连续性。本文档量化定义NovelHub平台的各项非功能指标，作为架构设计、开发实现和测试验证的硬性标准。

### 适用范围

本文档适用于所有开发、测试、运维人员，所有指标必须在验收时达到标准。

## Epic: 性能需求

### Feature 1: API性能指标

#### 需求ID: PERF-001

**需求名称**: API响应时间P95
**功能描述**: 95%的API请求响应时间控制在阈值内，保证用户体验流畅
**触发条件**: 任何API请求
**前置条件**: 系统正常负载（CPU使用率<70%）

**操作步骤**:
1. 客户端发送API请求
2. 服务器接收并处理
3. 返回响应给客户端

**正常流程**: 请求在阈值内完成处理和响应

**异常流程/边界情况**:
- 超过阈值：记录慢查询日志
- 超过5秒：请求自动超时返回

**权限控制**: 系统级

**输入输出规则**:
- 输入: 任意合法API请求
- 输出: 响应时间<阈值

**业务规则**:
- 普通API：P95 < 200ms
- 搜索API：P95 < 200ms
- 文件上传除外

**优先级**: P0

**验收标准**:
- AC1: Given 并发100用户 When 持续压测10分钟 Then P95响应时间≤200ms
- AC2: Given 正常业务流量 When 监控统计 Then 95%请求在200ms内完成
- AC3: Given 超过500ms的请求 When 发生 Then 自动记录慢查询日志

**来源**: 项目概述性能指标 + AI推导补充

### Feature 2: 前端性能指标

#### 需求ID: PERF-003

**需求名称**: 首屏加载时间FCP
**功能描述**: 首页首屏内容绘制时间控制在阈值内，提升用户留存
**触发条件**: 用户首次访问网站
**前置条件**: 用户网络环境为4G（下载速率≥10Mbps）

**操作步骤**:
1. 用户输入网址并访问
2. 浏览器下载资源
3. 解析并渲染页面
4. 首屏内容展示完成

**正常流程**: 1.5秒内完成首屏绘制

**异常流程/边界情况**:
- 弱网环境：显示加载骨架屏
- 加载超时：显示重试按钮

**权限控制**: 用户级

**输入输出规则**:
- 输入: 用户访问首页
- 输出: 首屏内容完整呈现

**业务规则**:
- 首屏加载时间FCP < 1.5s（4G环境）
- 启用Gzip压缩
- 静态资源CDN加速

**优先级**: P1

**验收标准**:
- AC1: Given 4G网络环境 When 使用Lighthouse测试 Then 首页FCP≤1.5s
- AC2: Given 页面加载过程中 When 资源未完成加载 Then 显示骨架屏占位
- AC3: Given 静态资源 When 发布 Then 自动压缩并上传CDN

**来源**: 项目概述性能指标

## Epic: 安全需求

### Feature 1: 认证与授权安全

#### 需求ID: SEC-001

**需求名称**: JWT令牌安全
**功能描述**: JWT认证机制符合安全标准，防止令牌泄露和伪造
**触发条件**: 用户登录、API调用
**前置条件**: 用户通过身份验证

**操作步骤**:
1. 用户登录成功
2. 服务端签发JWT令牌
3. 客户端存储令牌
4. 每次API请求携带令牌
5. 服务端验证令牌有效性

**正常流程**: 令牌验证通过，API正常响应

**异常流程/边界情况**:
- 令牌过期：返回401，提示重新登录
- 令牌篡改：验证失败，拒绝访问
- 令牌泄露：支持主动吊销令牌

**权限控制**: 系统级

**输入输出规则**:
- 输入: JWT令牌字符串
- 输出: 验证结果（通过/失败）

**业务规则**:
- JWT使用HS256算法，密钥长度≥256位
- 普通登录令牌有效期24小时
- 记住我令牌有效期7天
- 支持令牌黑名单机制

**优先级**: P0

**验收标准**:
- AC1: Given 篡改后的JWT令牌 When 调用API Then 验证失败返回401
- AC2: Given 超过有效期的令牌 When 使用 Then 自动失效提示重新登录
- AC3: Given 用户登出 When 执行 Then 令牌加入黑名单，无法继续使用

**来源**: 安全规范文档 + AI推导补充

#### 需求ID: SEC-002

**需求名称**: 密码安全策略
**功能描述**: 用户密码存储和验证符合安全最佳实践
**触发条件**: 用户注册、修改密码、登录
**前置条件**: 用户提交密码

**操作步骤**:
1. 用户提交明文密码
2. 服务端进行强度校验
3. 使用加密算法哈希处理
4. 存储哈希值（不存储明文）
5. 登录时使用相同算法验证

**正常流程**: 密码哈希存储和验证正常工作

**异常流程/边界情况**:
- 弱密码：注册时拒绝并提示
- 密码泄露：触发强制修改流程

**权限控制**: 用户级

**输入输出规则**:
- 输入: 明文密码字符串
- 输出: bcrypt哈希值

**业务规则**:
- 使用bcrypt算法，cost factor ≥ 12
- 密码长度8-20位，必须包含字母和数字
- 禁止使用常见弱密码
- 密码加盐，每个用户salt唯一

**优先级**: P0

**验收标准**:
- AC1: Given 相同密码 When 哈希处理 Then 每次生成不同的哈希值
- AC2: Given 弱密码尝试注册 When 提交 Then 系统拒绝并提示密码规则
- AC3: Given 数据库数据泄露 When 发生 Then 无法通过哈希值反推用户明文密码

**来源**: 安全规范文档 + AI推导补充

***

#### 需求ID: SEC-003

**需求名称**: 登录失败保护
**功能描述**: 防止暴力破解账号密码的保护机制
**触发条件**: 用户登录失败
**前置条件**: 账号密码验证失败

**操作步骤**:
1. 用户提交登录请求
2. 验证账号密码
3. 验证失败时计数
4. 达到阈值时触发锁定
5. 锁定期间拒绝登录请求

**正常流程**: 失败次数清零，登录成功

**异常流程/边界情况**:
- 连续5次失败：账号锁定30分钟
- 同IP大量尝试：IP封禁1小时

**权限控制**: 用户级

**输入输出规则**:
- 输入: 账号、密码
- 输出: 登录结果/锁定提示

**业务规则**:
- 连续5次密码错误锁定账号30分钟
- 锁定时间指数递增（30min→1h→2h...）
- 锁定期间不区分账号是否存在，统一提示

**优先级**: P0

**验收标准**:
- AC1: Given 连续5次密码错误 When 尝试登录 Then 账号锁定30分钟
- AC2: Given 锁定状态的账号 When 尝试登录 Then 返回统一错误信息，不泄露锁定状态
- AC3: Given 同一IP 10分钟内尝试100次登录 When 检测到 Then IP临时封禁1小时

**来源**: 登录失败锁定规则细粒度需求

### Feature 2: 数据安全与审计

#### 需求ID: SEC-004

**需求名称**: 管理操作审计
**功能描述**: 所有管理后台操作100%记录审计日志，可追溯可问责
**触发条件**: 管理员执行任何变更操作
**前置条件**: 管理员已登录后台

**操作步骤**:
1. 管理员执行操作（删除、修改、配置等）
2. 系统拦截操作请求
3. 记录完整审计信息
4. 执行业务操作
5. 记录操作结果

**正常流程**: 操作执行，审计日志完整记录

**异常流程/边界情况**:
- 操作失败：记录失败原因和异常栈
- 日志写入失败：阻止业务操作执行

**权限控制**: 管理员级

**输入输出规则**:
- 输入: 操作人、操作类型、操作参数、IP地址
- 输出: 审计日志记录

**业务规则**:
- 管理操作审计覆盖率100%
- 审计日志永久保存，不可删除和修改
- 日志包含：时间、用户、IP、操作、参数、结果

**优先级**: P1

**验收标准**:
- AC1: Given 管理员执行任何变更操作 When 操作完成 Then 审计日志中存在完整记录
- AC2: Given 审计日志记录 When 尝试删除或修改 Then 数据库拒绝执行
- AC3: Given 审计日志查询 When 需要 Then 可按用户、时间、操作类型筛选

**来源**: 项目概述安全指标

**权限控制**: 管理员级

**输入输出规则**:
- 输入: 操作确认、验证密码
- 输出: 操作执行结果

- 敏感操作覆盖率100%

- 批量处理≥10条必须二次确认

**优先级**: P1

**验收标准**:
- AC1: Given 管理员点击删除小说 When 点击 Then 弹出二次确认对话框
- AC2: Given 用户点击取消 When 二次确认 Then 操作终止无变更
- AC3: Given 批量删除超过10条记录 When 执行 Then 除确认外还需输入管理密码

**来源**: 项目概述安全指标 + AI推导补充

## Epic: 可用性需求

### Feature 1: 系统可用性

#### 需求ID: AVAIL-001

**需求名称**: 系统整体可用性
**功能描述**: 系统全年可用率达到99.9%，保障业务连续性
**触发条件**: 系统运行期间
**前置条件**: 正常运维，非计划内维护

**操作步骤**:
1. 健康检查接口每分钟探测
2. 记录不可用时间
3. 月度统计可用率

**正常流程**: 系统持续正常运行

**异常流程/边界情况**:
- 单实例故障：自动切换到冗余实例
- 机房故障：自动切换到备用机房

**权限控制**: 系统级

**输入输出规则**:
- 输入: 健康检查请求
- 输出: 200 OK表示正常

**业务规则**:
- 系统可用率 ≥ 99.9%
- 年度计划外停机时间 ≤ 8.76小时
- 单故障点自动切换时间 < 30秒

**优先级**: P1

**验收标准**:
- AC1: Given 月度统计 When 计算可用率 Then 达到或超过99.9%
- AC2: Given 单Web服务实例宕机 When 发生 Then 负载均衡器30秒内自动切流
- AC3: Given 计划外停机 When 发生 Then 运维人员5分钟内收到告警

**来源**: 项目概述可用性指标
