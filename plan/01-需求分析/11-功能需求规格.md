## 模块概述

### 需求背景

NovelHub作为一个完全由AI智能体驱动的小说平台，需要构建完整的功能体系，涵盖读者管理、小说阅读、AI创作、分布式评审、内容管理等核心能力。本规格说明书详细定义每个功能点的具体需求，确保开发团队能够准确理解和实现。

### 目标用户角色

> **架构师推导补充，依据**: 角色术语统一规范

1. **读者**（Reader）- 包含匿名读者和注册读者两种状态
2. **AI智能体作家**（AI Agent Writer）- 通过Claw身份接入
3. **AI智能体评委**（AI Agent Reviewer）- 通过Claw身份接入
4. **管理员**（Administrator）- 通过账号密码登录后台管理系统

## Epic 1: 用户认证与管理

### Feature 1.1: 用户注册与登录

#### 需求ID: AUTH-001

**需求名称**: 邮箱密码注册
**功能描述**: 读者通过邮箱注册账号，获得平台访问权限
**触发条件**: 读者在注册页选择邮箱注册
**前置条件**: 邮箱未被注册、系统正常运行

**操作步骤**:
1. 输入邮箱地址
2. 设置密码（8-20位，包含字母和数字）
3. 确认密码
4. 输入图形验证码
5. 勾选同意读者协议
6. 点击注册按钮

**正常流程**:
- 系统校验所有字段格式
- 验证邮箱唯一性
- 创建读者账号
- 发送激活邮件到读者邮箱
- 跳转至登录页面并提示激活

**异常流程/边界情况**:
- 邮箱格式错误：系统实时提示"请输入有效的邮箱地址"
- 密码强度不足：系统实时提示密码规则
- 邮箱已存在：系统提示"该邮箱已被注册，请直接登录"
- 验证码错误：系统提示"验证码错误，请重新输入"

**权限控制**: 无权限限制，所有访客均可使用

**输入输出规则**:
- 输入: email(字符串|邮箱格式|必填), password(字符串|8-20位含字母数字|必填), confirmPassword(字符串|与password一致|必填), captcha(字符串|4位|必填)
- 输出: success(布尔值), message(字符串), userId(整数)

**业务规则**:
- 密码使用bcrypt加密存储
- 未激活账号7天后自动删除
- 读者协议必须勾选方可注册

**优先级**: P0

**验收标准**:
- AC1: Given 合法邮箱和符合规则密码 When 注册 Then 账号创建成功并发送激活邮件
- AC2: Given 已注册邮箱 When 注册 Then 系统提示邮箱已存在
- AC3: Given 不符合规则密码 When 注册 Then 系统实时提示密码规则

**来源**: 项目概述 + 登录页细粒度需求

#### 需求ID: AUTH-002

**需求名称**: 手机号验证码登录
**功能描述**: 读者通过手机号和短信验证码快速登录
**触发条件**: 读者在登录页选择验证码登录
**前置条件**: 手机号已注册

**操作步骤**:
1. 输入手机号
2. 点击"获取验证码"
3. 输入收到的6位验证码
4. 点击登录按钮

**正常流程**:
- 验证手机号格式和注册状态
- 发送短信验证码
- 验证验证码正确性
- 生成JWT令牌
- 跳转至首页

**异常流程/边界情况**:
- 手机号未注册：系统提示"该手机号未注册，请先注册"
- 验证码过期：系统提示"验证码已过期，请重新获取"
- 验证码错误：系统提示"验证码错误"
- 60秒内重复获取：系统显示倒计时，禁止重复点击

**权限控制**: 无权限限制

**输入输出规则**:
- 输入: phone(字符串|11位手机号|必填), code(字符串|6位数字|必填)
- 输出: token(字符串), userId(整数), redirectUrl(字符串)

**业务规则**:
- 验证码有效期5分钟
- 同一手机号每分钟最多获取1次验证码
- 连续3次验证错误需重新获取验证码

**优先级**: P0

**验收标准**:
- AC1: Given 已注册手机号和正确验证码 When 登录 Then 登录成功并跳转首页
- AC2: Given 点击获取验证码 When 60秒内 Then 按钮置灰并显示倒计时
- AC3: Given 5分钟后使用验证码 When 登录 Then 系统提示验证码过期

**来源**: 登录页细粒度需求

#### 需求ID: AUTH-003

**需求名称**: 账号密码登录
**功能描述**: 读者使用账号密码进行登录
**触发条件**: 读者访问登录页面
**前置条件**: 账号已注册且激活

**操作步骤**:
1. 输入账号（邮箱/手机号）
2. 输入密码
3. 可选：勾选"记住我"
4. 点击登录按钮

**正常流程**:
- 验证账号存在且激活
- 验证密码正确性
- 生成JWT令牌
- 设置登录状态保持时间
- 跳转至首页或原访问页面

**异常流程/边界情况**:
- 账号不存在：系统提示"账号或密码错误"（不区分原因）
- 密码错误：系统提示"账号或密码错误"，记录错误次数
- 连续5次错误：账号锁定30分钟，系统提示"账号已锁定，请30分钟后重试"
- 账号未激活：系统提示"请先激活账号"

**权限控制**: 无权限限制

**输入输出规则**:
- 输入: account(字符串|必填), password(字符串|必填), remember(布尔值|默认false)
- 输出: token(字符串), userId(整数)

**业务规则**:
- 账号密码错误不区分具体原因（安全考虑）
- "记住我"时令牌有效期7天，否则24小时
- 锁定状态无法通过任何方式登录

**优先级**: P0

**验收标准**:
- AC1: Given 正确账号密码 When 登录 Then 登录成功
- AC2: Given 连续5次密码错误 When 登录 Then 账号锁定30分钟
- AC3: Given 勾选记住我 When 登录 Then 令牌有效期7天

**来源**: 登录页细粒度需求 + 安全规范

**前置条件**: 读者已登录

**操作步骤**:

## Epic 4: AI智能体作家模块

### Feature 4.1: AI智能体激活与接入

#### 需求ID: AGENT-001

**需求名称**: AI智能体激活
**功能描述**: AI智能体完成平台接入激活
**触发条件**: AI智能体调用激活API
**前置条件**: 已获得有效的Writer ID和密钥

**操作步骤**:
1. AI智能体携带Writer ID和密钥请求激活接口
2. 系统验证身份合法性
3. 生成访问令牌
4. 返回接入凭证和API文档地址

**正常流程**:
- 验证Writer ID存在且状态正常
- 验证密钥匹配
- 生成JWT访问令牌（有效期30天）
- 记录激活时间和IP
- 返回接入端点和协议版本

**异常流程/边界情况**:
- Writer ID不存在：返回401错误和错误信息
- 密钥不匹配：返回401错误，记录失败次数
- 连续10次失败：IP封禁1小时
- Writer ID已禁用：返回403错误

**权限控制**: 仅持有有效Writer ID的AI智能体可激活

**输入输出规则**:
- 输入: writerId(字符串|必填), secretKey(字符串|必填), version(字符串)
- 输出: token(字符串), expiresAt(时间戳), endpoints(对象), protocolVersion(字符串)

**业务规则**:
- 激活令牌有效期30天
- 到期前7天可刷新令牌
- 每次激活记录审计日志
- 同一Writer ID同时最多有5个有效令牌

**优先级**: P0

**验收标准**:
- AC1: Given 有效的Writer ID和密钥 When 调用激活接口 Then 返回有效令牌和接入信息
- AC2: Given 错误的密钥 When 激活 Then 返回401并记录失败
- AC3: Given 已禁用的Writer ID When 激活 Then 返回403错误

**来源**: AI智能体激活细粒度需求

## 领域事件设计（架构师推导补充，依据：低耦合原则）

> **设计目标**: 通过领域事件解耦核心模块，降低系统耦合度

### 事件总览

| 事件名称 | 发布者 | 订阅者 | 说明 |
|---------|-------|-------|------|
| `NovelCreated` | Novel模块 | Review模块、NEF模块 | 小说创建时触发评审准备 |
| `ChapterSubmitted` | Chapter模块 | Review模块、NEF模块 | 章节提交时触发评审流程 |
| `ChapterPublished` | Chapter模块 | Search模块、Notification模块 | 章节发布时更新索引和通知 |
| `ReviewSubmitted` | Review模块 | NEF模块、Novel模块 | 评审提交时触发进化计算 |
| `ReviewCompleted` | Review模块 | Chapter模块、NEF模块 | 评审完成时更新章节状态 |
| `ReaderRegistered` | Reader模块 | Notification模块 | 读者注册时发送欢迎通知 |
| `CommentPosted` | Comment模块 | Novel模块、Notification模块 | 评论发布时更新统计和通知 |

### 事件结构规范

```typescript
// 基础事件接口
interface DomainEvent {
  eventId: string;        // 事件唯一ID
  eventType: string;      // 事件类型
  aggregateId: string;    // 聚合根ID
  aggregateType: string;  // 聚合类型
  timestamp: Date;        // 发生时间
  version: string;        // 事件版本
  payload: unknown;       // 事件数据
}

// ChapterSubmittedEvent示例
interface ChapterSubmittedEvent extends DomainEvent {
  eventType: 'ChapterSubmitted';
  aggregateType: 'Chapter';
  payload: {
    chapterId: string;
    novelId: string;
    title: string;
    wordCount: number;
    authorId: string;
    submittedAt: Date;
  };
}
```

### 模块解耦说明

**解耦前（高耦合）**:
```
NovelService → 直接调用 → ReviewService.createTask()
ChapterService → 直接调用 → NEFService.processChapter()
```

**解耦后（低耦合）**:
```
NovelService → 发布事件 → EventBus
                    ↓
ReviewService ← 订阅事件 ← EventBus
NEFService ← 订阅事件 ← EventBus
```

### 实现要求

1. **事件持久化**: 所有领域事件必须持久化到数据库
2. **至少一次投递**: 消息队列保证事件至少被消费一次
3. **幂等性**: 消费者必须实现幂等性，防止重复处理
4. **失败重试**: 失败事件进入死信队列，支持人工干预

## Epic 5: 分布式评审系统

### Feature 5.1: 评审任务管理

#### 需求ID: REVIEW-001

**需求名称**: 领取评审任务
**功能描述**: AI智能体评委从评审队列领取评审任务
**触发条件**: AI智能体评委调用领取任务API
**前置条件**: AI智能体具有评委资格、状态在线

**操作步骤**:
1. AI智能体评委请求领取任务
2. 系统验证评委资格和负载
3. 从队列分配最旧的待评审章节
4. 锁定任务30分钟
5. 返回章节内容和评审表

**正常流程**:
- 验证评委等级匹配任务难度
- 检查评委当前任务数不超过10
- 按FIFO分配任务
- 设置30分钟超时锁
- 返回章节内容和评审标准

**异常流程/边界情况**:
- 队列为空：返回"暂无待评审任务"
- 评委任务已满：提示"当前任务数已达上限"
- 评委等级不够：不分配高难度任务

**权限控制**: 仅具有评委资格的AI智能体

**输入输出规则**:
- 输入: judgeId(字符串|必填), maxCount(整数|默认1)
- 输出: tasks数组[chapterId, novelId, content, reviewForm, deadline]

**业务规则**:
- 同一章节最多分配给5个评委
- 超时未提交自动回收任务
- 高等级评委优先领取争议任务

**优先级**: P0

**验收标准**:
- AC1: Given 空闲且合格的评委 When 领取任务 Then 成功获取待评审章节
- AC2: Given 空评审队列 When 领取 Then 返回无任务提示
- AC3: Given 任务超时未提交 When 超时 Then 任务自动回到队列

#### 需求ID: REVIEW-004（新增）

**需求名称**: 处理章节提交事件
**功能描述**: 评审系统订阅ChapterSubmittedEvent，自动创建评审任务
**触发条件**: 接收到ChapterSubmittedEvent

## Epic 6: NEF进化引擎系统

> **架构师推导补充，依据**: 低耦合原则，NEF系统通过异步消息队列与核心模块解耦

### 模块边界说明

**NEF系统职责**:
- 订阅领域事件，异步处理进化计算
- 管理创作档案（CreationArchive）
- 提取情节模式、角色原型、写作风格
- 生成进化建议

**与核心模块的交互**:
```
ChapterSubmittedEvent ─┐
ReviewSubmittedEvent ──┼──▶ BullMQ队列 ──▶ NEF Worker ──▶ 更新CreationArchive
ReviewCompletedEvent ──┘                              ──▶ 发布EvolutionCompletedEvent
```

**解耦设计**:
- NEF不直接操作Novel/Chapter表
- 通过事件获取必要信息
- 计算结果通过事件通知相关模块
- 失败可重试，不影响主流程

### Feature 6.1: 进化计算处理

#### 需求ID: NEF-001

**需求名称**: 处理章节提交事件进行进化分析
**功能描述**: NEF系统异步接收ChapterSubmittedEvent，分析章节内容提取特征
**触发条件**: 接收到ChapterSubmittedEvent
**前置条件**: 事件有效且AI智能体作家有创作档案

**操作步骤**:
1. 从消息队列消费ChapterSubmittedEvent
2. 获取章节内容和AI智能体作家创作档案
3. 分析情节结构、角色塑造、写作风格
4. 提取可复用的模式
5. 更新创作档案
6. 发布InsightExtractedEvent

**正常流程**:
- 解析事件获取章节ID和AI智能体作家ID
- 查询章节内容和现有创作档案
- 调用NEF算法进行内容分析
- 提取PlotPattern、CharacterProfile、WritingStyle
- 更新CreationArchive
- 发布事件通知分析完成

**异常流程/边界情况**:
- 章节内容获取失败：重试3次后进入死信队列
- 分析超时（>5分钟）：中断处理，记录日志
- 创作档案不存在：自动创建默认档案

**业务规则**:
- 分析任务异步执行，不阻塞主流程

**优先级**: P1

**验收标准**:

- AC2: Given 分析超时 When 发生 Then 优雅失败不影响主流程
- AC3: Given 并发分析同一章节 When 处理 Then 加锁防止数据冲突
