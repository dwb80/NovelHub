本文档补充NEF进化引擎在100万AI智能体规模下的性能和架构需求，确保系统可水平扩展。

### 1.2 范围
- 高并发进化请求处理
- 大规模数据统计计算

| 术语 | 定义 |

## 2. 功能需求

### 2.1 高并发进化请求处理

#### F-NEF-SCALE-001: 进化请求队列化

**需求描述**
进化请求通过BullMQ队列异步处理，支持高并发请求。

**业务规则**:
- 进化请求先入队，返回任务ID
- 后台Worker消费队列执行进化
- 支持优先级队列（高/中/低）
- 队列持久化，服务重启不丢失

**性能指标**:
| 指标 | 目标值 |
|------|--------|
| 入队响应时间 | < 50ms |
| 队列吞吐量 | > 1000 req/s |
| 队列积压告警 | > 10000 条 |

**验收标准**:
- AC1: Given 1000并发进化请求 When 提交 Then 全部在50ms内入队成功
- AC2: Given 队列积压超过10000 When 发生 Then 触发告警通知
- AC3: Given 服务重启 When 恢复 Then 队列任务不丢失继续处理

---

#### F-NEF-SCALE-002: 进化结果缓存

**需求描述**
进化结果使用Redis缓存，减少重复计算。

**业务规则**:
- 相同参数的进化请求命中缓存
- 缓存有效期24小时
- 缓存命中率目标 > 80%

**性能指标**:
| 指标 | 目标值 |
|------|--------|
| 缓存命中响应 | < 10ms |
| 缓存写入响应 | < 20ms |
| 缓存容量 | > 100万条 |

---

### 2.2 大规模数据统计计算

#### F-NEF-SCALE-003: 平台统计增量计算

**需求描述**
平台统计数据使用增量计算，避免全量扫描。

**业务规则**:
- 统计数据定时增量更新（每5分钟）
- 使用Redis存储统计快照
- 支持统计数据回溯查询

**性能指标**:
| 指标 | 目标值 |
|------|--------|
| 增量计算时间 | < 30s |
| 统计查询响应 | < 100ms |
| 数据延迟 | < 5分钟 |

**验收标准**:
- AC1: Given 100万Claw数据 When 计算平台统计 Then 30秒内完成
- AC2: Given 统计数据查询 When 请求 Then 100ms内返回结果
- AC3: Given Claw数据变更 When 5分钟后 Then 统计数据自动更新

---

### 2.3 进化结果验证与回滚

#### F-NEF-SCALE-004: 进化结果验证机制

**需求描述**
进化结果应用前进行验证，确保内容质量。

**业务规则**:
- 进化后内容进行质量评分
- 评分低于阈值自动拒绝
- 验证失败记录原因

**验证规则**:
| 验证项 | 阈值 | 处理 |
|--------|------|------|
| 内容长度变化 | > 50% | 拒绝 |
| 质量评分 | < 5.0 | 拒绝 |
| 敏感词检测 | 命中 | 拒绝 |

**验收标准**:
- AC1: Given 进化后内容质量评分4.0 When 验证 Then 自动拒绝并记录原因
- AC2: Given 进化后内容长度减少60% When 验证 Then 自动拒绝
- AC3: Given 进化后内容包含敏感词 When 验证 Then 自动拒绝并标记

---

#### F-NEF-SCALE-005: 进化结果回滚机制

**需求描述**
支持进化结果回滚到之前版本。

**业务规则**:
- 保留最近10次进化历史
- 回滚操作需要二次确认
- 回滚后更新进化索引

**API接口**:
```
POST /api/v1/nef/evolution/{id}/rollback
Response: {
  success: boolean,
  previousVersion: string,
  currentVersion: string
}
```

**验收标准**:
- AC1: Given 进化已应用 When 执行回滚 Then 内容恢复到进化前状态
- AC2: Given 回滚操作 When 执行 Then 需要用户二次确认
- AC3: Given 进化历史超过10次 When 查询 Then 保留最近10次记录

---

### 2.4 水平扩展架构

#### F-NEF-SCALE-006: 无状态服务设计

**需求描述**
NEF服务设计为无状态，支持水平扩展。

**架构要求**:
- 服务不存储会话状态
- 状态存储在Redis
- 支持Kubernetes自动扩缩容

**扩展指标**:
| 指标 | 目标值 |
|------|--------|
| 最小实例数 | 2 |
| 最大实例数 | 20 |
| 扩容触发条件 | CPU > 70% |
| 缩容触发条件 | CPU < 30% 持续5分钟 |

---

#### F-NEF-SCALE-007: 数据库分片策略

**需求描述**
大规模数据支持分片存储。

**分片规则**:
| 数据表 | 分片键 | 分片策略 |
|--------|--------|---------|
| evolution_history | clawId | Hash分片 |
| creation_insights | novelId | Hash分片 |
| plot_patterns | archiveId | Hash分片 |

**验收标准**:
- AC1: Given 100万Claw数据 When 查询 Then 单次查询响应 < 200ms
- AC2: Given 数据写入 When 执行 Then 自动路由到正确分片
- AC3: Given 分片节点故障 When 发生 Then 自动切换到副本

## 4. 接口清单

### 4.1 新增接口

| 接口 | 方法 | 描述 |
|------|------|------|
| `/api/v1/nef/evolution/async` | POST | 异步进化请求 |
| `/api/v1/nef/evolution/{id}/status` | GET | 查询进化状态 |
| `/api/v1/nef/evolution/{id}/rollback` | POST | 回滚进化结果 |
| `/api/v1/nef/queue/stats` | GET | 队列统计信息 |

### 4.2 接口详情

#### 异步进化请求

```yaml
POST /api/v1/nef/evolution/async
Authorization: Bearer {token}
Content-Type: application/json

Request:
{
  "chapterId": "uuid",
  "strategy": "REFINE" | "RESTRUCTURING" | "INNOVATION",
  "priority": "high" | "medium" | "low",
  "callbackUrl": "https://..."  # 可选，完成后回调
}

Response 202:
{
  "taskId": "uuid",
  "status": "QUEUED",
  "estimatedTime": 30,
  "message": "进化任务已入队"
}
```

#### 查询进化状态

```yaml
GET /api/v1/nef/evolution/{taskId}/status

Response 200:
{
  "taskId": "uuid",
  "status": "QUEUED" | "PROCESSING" | "COMPLETED" | "FAILED",
  "progress": 0-100,
  "result": {
    "evolvedContent": "...",
    "confidence": 0.85,
    "changes": []
  },
  "error": null | "错误信息",
  "createdAt": "2026-04-19T10:00:00Z",
  "completedAt": "2026-04-19T10:00:30Z"
}
```

## 5. 测试用例
