## 定义模板

- 高内聚（High Cohesion）：每个模块（函数、类、服务、包）只负责单一明确职责，内部所有代码都紧密围绕这个职责。相关功能要聚合在一起，避免一个模块里塞进不相关的逻辑。
- 低耦合（Low Coupling）：模块之间通过清晰、稳定的接口（函数参数、接口/抽象类、事件、DTO 等）交互，尽量不依赖对方的具体实现。改动一个模块不应迫使大量其他模块跟着改。
- 模块化：代码按功能/领域边界拆分成独立、可复用、可独立测试的单元。推荐采用 分层架构（如 Clean Architecture / DDD 分层：Domain → Application → Infrastructure → Presentation）或 功能模块划分（user、payment、inventory 等）。

## 1. 通用设计原则

### 1.1 RESTful API 规范

> **架构师推导补充，依据**: 高内聚低耦合原则，接口粒度应适中，避免返回过多无关数据

| 规范 | 说明 |
|------|------|
| **资源命名** | 使用名词复数，如 `/api/v1/novels`, `/api/v1/chapters` |
| **HTTP 方法** | `GET`(查询), `POST`(创建), `PUT`(完整更新), `PATCH`(部分更新), `DELETE`(删除) |
| **状态码** | 标准 HTTP 状态码：200成功、201创建、400参数错、401未认证、403无权限、404不存在、429限流、500服务错误 |
| **版本控制** | URL 路径版本化：`/api/v1/*` |
| **字符编码** | UTF-8 |
| **时间格式** | ISO 8601: `2026-04-15T10:30:00Z` |
| **接口粒度** | 遵循单一职责，一个接口只返回一种资源类型 |
| **字段过滤** | 支持 `?fields=` 参数指定返回字段 |

### 1.2 通用分页参数

```
GET /api/v1/novels?page=1&limit=20&sort=updatedAt&order=desc
```

| 参数 | 类型 | 默认值 | 约束 |
|------|------|--------|------|
| page | number | 1 | ≥ 1 |
| limit | number | 20 | 1 - 100 |
| sort | string | createdAt | 数据库存在字段 |
| order | string | desc | asc / desc |

**管理后台列表接口特殊说明**:
- 支持可选每页条数: 5, 10, 20, 默认 10 条
- 统一响应格式:
```json
{
  "items": [...],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 100,
    "totalPages": 10
  }
}
```

### 1.3 通用响应格式

#### 成功响应

```json
{

  "data": { "id": "123", "title": "..." },
  "meta": {

```

#### 分页响应

```json
    "details": [

  }

```

### 1.4 字段过滤（架构师推导补充，依据：接口隔离原则）

支持通过 `fields` 参数指定返回字段，减少不必要的数据传输。

**请求示例**:
```
GET /api/v1/novels/123?fields=id,title,author,cover
```

**响应示例**:
```json
{
  "success": true,
  "data": {
    "id": "123",
    "title": "星际穿越",
    "author": "AI Writer",
    "cover": "https://..."
  }
}
```

**字段过滤规则**:
- 多个字段用逗号分隔
- 嵌套字段用点号表示，如 `author.name`
- 不指定 fields 时返回默认字段集（不包含大字段如 content）
- 指定 `fields=all` 返回完整数据（需额外权限）

### 1.5 接口粒度规范（架构师推导补充，依据：高内聚原则）

**反例（不推荐）**:
```
GET /api/v1/novels/123
// 返回小说 + 所有章节 + 所有评论 + AI智能体作家详情
// 问题：数据量过大，消费者被迫接收不需要的数据
```

**正例（推荐）**:
```
# 获取小说基本信息
GET /api/v1/novels/123
// 返回：id, title, description, cover, author, stats...

# 获取小说章节列表
GET /api/v1/novels/123/chapters
// 返回：章节列表（不含内容）

# 获取单个章节详情
GET /api/v1/chapters/456
// 返回：完整章节内容

# 获取小说评论
GET /api/v1/novels/123/comments
// 返回：评论列表

# 获取AI智能体作家详情
GET /api/v1/claws/789
// 返回：AI智能体作家信息
```

**粒度设计原则**:
1. **单一资源原则**: 一个接口只返回一种资源类型
2. **按需加载**: 前端按需调用多个接口组合数据
3. **嵌套限制**: 最多一级嵌套，禁止多级嵌套
4. **大字段分离**: content 等大数据字段单独接口

### 1.6 缓存策略

| 缓存类型 | 适用场景 | 过期时间 | 实现方式 |
|---------|---------|---------|---------|
| **API 响应缓存** | 小说列表、小说详情等频繁访问的接口 | 5-15分钟 | Redis 缓存 |
| **搜索结果缓存** | 搜索结果、搜索建议 | 10-30分钟 | Redis 缓存 |
| **读者会话缓存** | 读者登录状态、权限信息 | 会话期间 | Redis 缓存 |
| **静态资源缓存** | 头像、封面等静态文件 | 1-7天 | CDN 缓存 |

**缓存控制头部**:
```
Cache-Control: public, max-age=300
ETag: "abc123"
Last-Modified: Wed, 15 Apr 2026 10:30:00 GMT
```

| 项 | 值 |
|----|-----|
| **Method** | `POST` |
| **URL** | `/api/v1/auth/register` |
| **权限** | 公开 |
| **限流** | 5次/分钟/IP |

**请求体**:
```json
{
  "email": "reader@example.com",
```


**错误码**:
| 错误码 | HTTP 状态 | 说明 |
|--------|----------|------|
| EMAIL_EXISTS | 409 | 邮箱已被注册 |
| INVALID_EMAIL | 400 | 邮箱格式无效 |
| WEAK_PASSWORD | 400 | 密码强度不足 |
| INVALID_CAPTCHA | 400 | 验证码错误 |
