## 定义模板

- 高内聚（High Cohesion）：每个模块（函数、类、服务、包）只负责单一明确职责，内部所有代码都紧密围绕这个职责。相关功能要聚合在一起，避免一个模块里塞进不相关的逻辑。
- 低耦合（Low Coupling）：模块之间通过清晰、稳定的接口（函数参数、接口/抽象类、事件、DTO 等）交互，尽量不依赖对方的具体实现。改动一个模块不应迫使大量其他模块跟着改。
- 模块化：代码按功能/领域边界拆分成独立、可复用、可独立测试的单元。推荐采用 分层架构（如 Clean Architecture / DDD 分层：Domain → Application → Infrastructure → Presentation）或 功能模块划分（user、payment、inventory 等）。

## 4. 关键技术决策 (ADR)

### ADR-001: 使用模块化单体而非微服务

#### Status
Accepted

#### Context
项目初期团队规模小（3-5人），边界尚不清晰，微服务会带来额外复杂度。

#### Decision
采用 **模块化单体 (Modular Monolith)** 架构，基于 NestJS 的 Module 系统进行严格模块划分。

#### Consequences
✅ **优势**：
- 开发效率高，无需跨服务调用
- 事务一致性容易保证
- 部署简单，运维成本低
- 边界清晰后可平滑拆分微服务

⚠️ **劣势**：
- 需严格遵守模块边界，禁止跨模块直接调用
- 无法独立扩容单个模块
- 所有模块共享同一数据库连接池

**权衡**：开发效率优先于独立扩容能力。边界清晰后（6个月后）再考虑按领域拆分微服务。

***

### ADR-002: 使用 Prisma 而非 TypeORM

#### Status
Accepted

#### Context
需要类型安全的数据库访问层，减少运行时错误。

#### Decision
采用 Prisma 作为 ORM。

#### Consequences
✅ **优势**：
- 类型安全，编译时捕获错误
- Schema 即代码，自动生成 Client
- 迁移系统简单直观
- 支持复杂关系查询

⚠️ **劣势**：
- 复杂 SQL 需要 $queryRaw
- 生态相比 TypeORM 较小

**权衡**：类型安全优先级高于生态成熟度。

***

### ADR-003: 使用 Redis + BullMQ 做异步任务

#### Status
Accepted

#### Context
评审任务、NEF进化、通知推送需要异步处理。

#### Decision
采用 Redis + BullMQ 作为异步任务队列系统。

#### Consequences
✅ **优势**：
- 任务持久化，不丢失
- 支持延迟任务、重试、优先级
- 自动重试和死信队列
- 内置监控面板

⚠️ **劣势**：
- 依赖 Redis 可用性

**权衡**：功能完整优先于额外依赖。

***

### ADR-004: 搜索技术选型 - PostgreSQL FTS → OpenSearch

#### Status
Accepted

#### Context
全文搜索功能需要支持小说标题、简介搜索。

#### Decision
- **当前阶段**: 使用 **PostgreSQL 全文搜索 (FTS)**，暂不引入搜索引擎
- **未来规划**: 迁移至 **OpenSearch**（详见 [ADR-001](../adr/ADR-001-使用OpenSearch替代Elasticsearch.md)）
- **明确决策**: 本项目不使用 Elasticsearch

#### Consequences
✅ **优势**：
- 无额外组件依赖
- 运维简单
- 数据一致性天然保证

⚠️ **劣势**：
- 数据量超过100万后性能下降
- 高级相关性评分能力有限

**权衡**：架构简单优先于搜索性能。日活>10万或小说>10万本时迁移至OpenSearch。

**技术决策依据**: OpenSearch 使用 Apache 2.0 许可证，无商业限制，与 Elasticsearch 7.x API 兼容。

## 5. 核心质量属性实现方案

### 5.1 性能方案

| 质量属性 | 目标值 | 实现方案 |
|----------|--------|----------|
| API P95 响应时间 | < 200ms | 1. Redis 缓存热点数据<br>2. 数据库索引优化<br>3. Prisma 查询优化 |
| 数据库查询 P99 | < 100ms | 1. 必要索引全覆盖<br>2. 避免 N+1 查询<br>3. 读写分离（后期） |
| 首页 FCP | < 1.5s | 1. Next.js SSR + Streaming<br>2. 静态资源 CDN<br>3. 图片懒加载 |

### 5.2 可靠性方案

| 质量属性 | 目标值 | 实现方案 |
|----------|--------|----------|
| 系统可用率 | ≥ 99.9% | 1. K8s 多副本 + 自动重启<br>2. 健康检查 + 自动熔断<br>3. 数据库主从切换 |
| 任务成功率 | ≥ 99% | 1. BullMQ 自动重试（指数退避）<br>2. 死信队列告警<br>3. 幂等性设计 |

### 5.3 安全方案

| 质量属性 | 实现方案 |
|----------|----------|
| 认证安全 | 1. bcrypt 加密密码（cost=12）<br>2. JWT 短有效期 + 刷新令牌<br>3. 令牌黑名单机制 |
| 数据保护 | 1. HTTPS 全站加密<br>2. SQL 注入防护（Prisma 天然）<br>3. XSS 防护 + CSP |
| 审计合规 | 1. 所有管理操作审计日志<br>2. 敏感数据加密存储<br>3. GDPR 数据导出/删除 |
