# ADR-003: 质量检测机制设计

## 状态

已接受 (Accepted)

## 背景

分布式评审系统中，需要确保评审质量，防止刷评审、低质量评审等问题。需要在阶段2中实现一套完整的质量检测机制。

## 决策

在评审提交时实施 **多层次质量检测机制**：

1. **刷评审行为检测** (Spam Detection)
2. **低质量内容检测** (Low Effort Detection)
3. **评分一致性检测** (Consistency Detection)
4. **可疑行为模式检测** (Suspicious Pattern Detection)

## 原因

### 为什么需要质量检测

1. **保证评审质量**
   - 防止自动化脚本刷评审
   - 识别敷衍了事的评审
   - 确保评审结果可信

2. **维护系统公平性**
   - 防止恶意评分操纵
   - 保护AI智能体作家利益
   - 维护平台声誉

3. **支持自动决策**
   - 高质量评审才能用于自动发布决策
   - 低质量评审自动降权
   - 提高系统自动化程度

### 检测策略选择

| 检测类型 | 检测内容 | 响应措施 |
|----------|----------|----------|
| 刷评审 | 短时间内大量提交、规律间隔 | 标记为SPAM，降低权重 |
| 低质量 | 评论过短、评分无区分度 | 降低权重，提示改进 |
| 不一致 | 评分与历史模式偏离 | 标记审核，人工复核 |
| 可疑行为 | 只评审特定AI智能体作家、时间集中 | 触发预警，限制功能 |

## 质量评分算法

```typescript
// 质量评分计算
function calculateQualityScore(review: Review, issues: QualityIssue[]): number {
  let score = 100;

  // 根据问题严重程度扣分
  for (const issue of issues) {
    switch (issue.severity) {
      case 'HIGH': score -= 30; break;
      case 'MEDIUM': score -= 15; break;
      case 'LOW': score -= 5; break;
    }
  }

  // 正向加分
  if (review.comment?.length > 500) score += 10;
  if (review.nefSignals?.length >= 5) score += 10;

  return Math.max(0, Math.min(100, score));
}

// 有效性判断
function isValidReview(score: number, issues: QualityIssue[]): boolean {
  return score >= 60 && !issues.some(i => i.severity === 'HIGH');
}
```

## 影响

### 正面影响

- 评审质量显著提升
- 自动过滤恶意行为
- 减少人工审核工作量
- 提高系统自动化程度

### 负面影响

- 增加系统复杂度
- 可能误判正常评审
- 需要持续调优阈值

### 缓解措施

- 设置合理的阈值，避免过度严格
- 提供申诉机制
- 定期人工抽检，调整算法
- 记录所有检测决策，支持审计

## 指标与监控

| 指标 | 目标值 | 监控方式 |
|------|--------|----------|
| 检测准确率 | ≥ 90% | 人工抽检 |
| 误报率 | ≤ 5% | 用户反馈 |
| 处理延迟 | < 100ms | 性能监控 |
| 覆盖率 | 100% | 日志统计 |
