## 完整示例

### TC-HU-001: 用户注册-正常流程

| 属性 | 内容 |
|------|------|
| **用例ID** | TC-HU-001 |
| **用例名称** | 用户注册-正常流程 |
| **测试类型** | 功能测试 |
| **优先级** | P0 |
| **所属模块** | 用户系统 |
| **所属需求** | HU-REG-001 |
| **关联用例** | TC-HU-002, TC-HU-003 |
| **创建日期** | 2026-04-12 |
| **最后更新** | 2026-04-12 |
| **创建人** | 测试工程师 |

**测试目的**:
验证用户使用有效信息可以成功注册账号

**前置条件**:
1. 注册页面可访问
2. 邮箱未被注册
3. 网络连接正常

**测试数据**:
```json
{
  "username": "testuser001",
  "email": "test001@example.com",
  "password": "Test@123456",
  "confirmPassword": "Test@123456"
}
```

**测试步骤**:

| 步骤 | 操作 | 预期结果 | 验证方法 |
|------|------|----------|----------|
| 1 | 访问注册页面 `/register` | 页面加载完成，显示注册表单 | 验证页面标题和表单元素 |
| 2 | 输入用户名 `testuser001` | 用户名显示在输入框 | 验证输入框值 |
| 3 | 输入邮箱 `test001@example.com` | 邮箱显示在输入框 | 验证输入框值 |
| 4 | 输入密码 `Test@123456` | 密码以掩码显示 | 验证输入框类型 |
| 5 | 输入确认密码 `Test@123456` | 确认密码显示 | 验证输入框值 |
| 6 | 点击"注册"按钮 | 显示加载状态，然后跳转 | 验证页面跳转和Toast提示 |
| 7 | 检查邮箱 | 收到验证邮件 | 验证邮件内容 |

**预期结果详情**:
- ✅ 注册表单正确加载
- ✅ 所有输入框可正常输入
- ✅ 密码显示为掩码
- ✅ 点击注册后显示加载状态
- ✅ 注册成功后跳转至首页
- ✅ 显示"注册成功"Toast提示
- ✅ 发送验证邮件到注册邮箱
- ✅ 数据库中创建用户记录

**验证检查点**:
- [ ] 页面URL正确
- [ ] 表单元素完整
- [ ] 输入验证通过
- [ ] 注册成功跳转
- [ ] Toast提示正确
- [ ] 邮件发送成功
- [ ] 数据库记录正确

**后置处理**:
1. 删除测试用户数据
2. 清理测试邮箱

**自动化信息**:

| 属性 | 内容 |
|------|------|
| **可自动化** | 是 |
| **自动化优先级** | 高 |
| **测试框架** | Playwright |
| **脚本路径** | `tests/e2e/register.spec.ts` |
| **数据驱动** | 是 |

## 优先级定义

| 优先级 | 定义 | 执行时机 |
|--------|------|----------|
| **P0** | 核心功能，阻塞性缺陷 | 每轮测试必测 |
| **P1** | 重要功能，影响用户体验 | 回归测试必测 |
| **P2** | 一般功能，有替代方案 | 时间允许时测试 |
| **P3** | 边缘功能，影响较小 | 可选测试 |

---

## 测试类型定义

| 测试类型 | 说明 | 适用场景 |
|----------|------|----------|
| **功能测试** | 验证业务功能正确性 | 所有功能点 |
| **接口测试** | 验证API行为 | 后端接口 |
| **UI测试** | 验证界面元素和交互 | 前端页面 |
| **性能测试** | 验证性能指标 | 关键路径 |
| **安全测试** | 验证安全防护 | 敏感功能 |
| **兼容测试** | 验证多环境支持 | 跨浏览器/设备 |
