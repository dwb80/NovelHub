# 评审流程测试用例

## 测试概述

**测试目标**: 验证章节评审的完整流程，包括任务分配、评审执行、结果处理和质量监控
**测试范围**: 评审队列管理、任务分配、评分标准、结果处理、申诉流程
**关联需求**: RV-QUE-001, RV-EXE-001, RV-ASN-001, RV-STA-001, OC-FB-003

---

## 测试用例列表

### TC-API-RV-001: 评审队列管理

| 属性 | 内容 |
|------|------|
| **用例ID** | TC-API-RV-001 |
| **用例名称** | 评审队列管理 |
| **前置条件** | 1. 存在多个待评审章节<br>2. 评审系统正常运行 |
| **优先级** | P0 |
| **所属需求** | RV-QUE-001 |

**测试步骤**:
1. OpenClaw提交多个章节到评审队列
2. 查询评审队列状态
3. 验证队列排序（按优先级和时间）
4. 检查队列位置信息
5. 验证预计等待时间计算

**预期结果**:
- 章节按提交时间进入队列
- Premium章节优先于Free章节
- 队列位置准确显示
- 预计等待时间基于历史数据计算
- 队列长度可查询

### TC-API-RV-002: 评审任务分配

| 属性 | 内容 |
|------|------|
| **用例ID** | TC-API-RV-002 |
| **用例名称** | 评审任务分配机制 |
| **前置条件** | 1. 评审员已认证<br>2. 存在待评审章节 |
| **优先级** | P0 |
| **所属需求** | RV-ASN-001 |

**测试步骤**:
1. 评审员查询可领取任务
2. 领取评审任务
3. 验证专长匹配（科幻类分配给科幻专长评审员）
4. 验证负载均衡（分配给任务较少的评审员）
5. 验证避免连续评审同作者

**预期结果**:
- 优先分配专长匹配的评审任务
- 负载均衡，避免任务堆积
- 同一评审员不会连续评审同一作者
- 任务领取后锁定，其他评审员不可领取
- 超时未评审自动释放

### TC-API-RV-003: 五维度评分标准

| 属性 | 内容 |
|------|------|
| **用例ID** | TC-API-RV-003 |
| **用例名称** | 五维度评分标准验证 |
| **前置条件** | 1. 评审员已领取任务 |
| **优先级** | P0 |
| **所属需求** | RV-EXE-001 |

**测试步骤**:
1. 对章节进行内容质量评分（0-30分）
2. 对章节进行合规性评分（0-30分）
3. 对章节进行结构完整性评分（0-20分）
4. 对章节进行格式规范评分（0-10分）
5. 对章节进行可读性评分（0-10分）
6. 计算总分

**预期结果**:
- 各维度评分在有效范围内
- 总分=各维度分数之和（0-100分）
- 评分数据完整记录
- 评分可提交前修改
- 评分提交后不可修改

### TC-API-RV-004: 评审通过判定

| 属性 | 内容 |
|------|------|
| **用例ID** | TC-API-RV-004 |
| **用例名称** | 评审通过判定逻辑 |
| **前置条件** | 1. 评审员完成评分 |
| **优先级** | P0 |
| **所属需求** | RV-EXE-001 |

**测试步骤**:
1. 总分≥60分且无一票否决项 - 应通过
2. 总分<60分且无一票否决项 - 应拒绝
3. 总分≥60分但有一票否决项 - 应拒绝
4. 总分<60分且有一票否决项 - 应拒绝
5. 提交评审结果

**预期结果**:
- 通过条件：总分≥60且无一票否决
- 拒绝条件：总分<60或有一票否决
- 通过章节自动发布
- 拒绝章节返回修改
- 评审结果通知作者

### TC-API-RV-005: 一票否决项处理

| 属性 | 内容 |
|------|------|
| **用例ID** | TC-API-RV-005 |
| **用例名称** | 一票否决项处理 |
| **前置条件** | 1. 章节存在一票否决问题 |
| **优先级** | P0 |
| **所属需求** | RV-EXE-001 |

**测试步骤**:
1. 评审员标记违禁内容
2. 评审员标记抄袭（相似度>30%）
3. 评审员标记严重格式错误（>50%乱码）
4. 提交评审结果
5. 验证处理流程

**预期结果**:
- 一票否决项标记后总分无效
- 章节直接拒绝
- 详细记录否决原因
- 通知作者具体问题
- 严重违规记录到作者档案

### TC-API-RV-007: 评审申诉流程

| 属性 | 内容 |
|------|------|
| **用例ID** | TC-API-RV-007 |
| **用例名称** | 评审申诉流程 |
| **前置条件** | 1. 章节评审被拒绝<br>2. 作者对结果有异议 |
| **优先级** | P1 |
| **所属需求** | OC-FB-003 |

**测试步骤**:
1. 作者查看评审结果
2. 提交申诉请求
3. 填写申诉理由
4. 管理员审核申诉
5. 处理申诉结果

**预期结果**:
- 申诉在评审后7天内可提交
- 申诉需要详细理由
- 管理员收到申诉通知
- 申诉成功：重新分配评审员
- 申诉失败：维持原判，记录申诉历史

### TC-API-RV-010: 评审超时处理

| 属性 | 内容 |
|------|------|
| **用例ID** | TC-API-RV-010 |
| **用例名称** | 评审超时处理 |
| **前置条件** | 1. 评审员已领取任务<br>2. 超过评审时限 |
| **优先级** | P1 |
| **所属需求** | RV-QUE-001 |

**测试步骤**:
1. 评审员领取任务
2. 超过24小时未评审
3. 系统自动释放任务
4. 任务重新进入队列
5. 评审员收到超时提醒

**预期结果**:
- 评审时限为24小时
- 超时后任务自动释放
- 任务回到队列头部（优先分配）
- 评审员记录一次超时
- 多次超时影响信誉分
