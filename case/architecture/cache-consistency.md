# 缓存一致性测试用例

## 测试概述

**测试目标**: 验证系统缓存的一致性、可靠性和容错能力，包括缓存穿透、击穿、雪崩防护
**测试范围**: Redis缓存、本地缓存、缓存同步、缓存失效策略、异常场景处理
**关联需求**: ARC-CCH-001, ARC-PEN-001, ARC-BRK-001, ARC-AVA-001

---

## 测试用例列表

### TC-ARC-001: 缓存穿透防护

| 属性 | 内容 |
|------|------|
| **用例ID** | TC-ARC-001 |
| **用例名称** | 缓存穿透防护测试 |
| **前置条件** | 1. Redis缓存服务正常运行<br>2. 布隆过滤器已配置 |
| **优先级** | P0 |
| **所属需求** | ARC-PEN-001 |

**测试步骤**:
1. 查询不存在的小说ID
2. 观察缓存和数据库访问情况
3. 重复查询同一不存在ID
4. 验证布隆过滤器拦截
5. 检查空值缓存策略

**预期结果**:
- 首次查询：布隆过滤器判定不存在，直接返回404
- 或：缓存空值（null），过期时间5分钟
- 重复查询不访问数据库
- 数据库查询次数不随请求增加
- 防护机制日志记录

### TC-ARC-002: 缓存击穿防护

| 属性 | 内容 |
|------|------|
| **用例ID** | TC-ARC-002 |
| **用例名称** | 缓存击穿防护测试 |
| **前置条件** | 1. 热点数据已缓存<br>2. 缓存即将过期 |
| **优先级** | P0 |
| **所属需求** | ARC-BRK-001 |

**测试步骤**:
1. 设置热点数据缓存TTL为10秒
2. 模拟100并发请求访问热点数据
3. 等待缓存过期
4. 观察缓存重建过程
5. 检查数据库访问次数

**预期结果**:
- 使用互斥锁（Mutex）防止并发重建
- 只有一个请求访问数据库
- 其他请求等待缓存重建完成
- 数据库访问次数=1（而非100）
- 热点数据永不过期策略（逻辑过期）

### TC-ARC-003: 缓存雪崩防护

| 属性 | 内容 |
|------|------|
| **用例ID** | TC-ARC-003 |
| **用例名称** | 缓存雪崩防护测试 |
| **前置条件** | 1. 大量缓存数据设置相同TTL<br>2. 高并发访问环境 |
| **优先级** | P0 |
| **所属需求** | ARC-AVA-001 |

**测试步骤**:
1. 批量设置1000个缓存项，TTL=60秒
2. 模拟500并发用户访问
3. 等待60秒让缓存集中过期
4. 观察系统响应情况
5. 检查数据库压力

**预期结果**:
- TTL添加随机偏移（±10%）
- 缓存过期时间分散
- 数据库压力平稳
- 系统响应时间无剧烈波动
- 熔断机制在压力过大时触发

### TC-ARC-004: 缓存与数据库一致性

| 属性 | 内容 |
|------|------|
| **用例ID** | TC-ARC-004 |
| **用例名称** | 缓存与数据库一致性测试 |
| **前置条件** | 1. 缓存和数据库正常运行<br>2. 存在可修改的数据 |
| **优先级** | P0 |
| **所属需求** | ARC-CCH-001 |

**测试步骤**:
1. 查询数据并缓存
2. 修改数据库中的数据
3. 观察缓存更新策略
4. 查询验证数据一致性
5. 测试延迟双删策略

**预期结果**:
- Cache-Aside模式：更新时先更新数据库，再删缓存
- 或Write-Through模式：同步更新缓存和数据库
- 读取时缓存未命中则从数据库加载
- 最终一致性保证
- 延迟双删防止脏读

### TC-ARC-005: 分布式缓存同步

| 属性 | 内容 |
|------|------|
| **用例ID** | TC-ARC-005 |
| **用例名称** | 分布式缓存同步测试 |
| **前置条件** | 1. 多实例部署<br>2. 使用Redis集群 |
| **优先级** | P1 |
| **所属需求** | ARC-CCH-001 |

**测试步骤**:
1. 实例A写入缓存
2. 实例B读取同一缓存Key
3. 实例A更新数据并删除缓存
4. 实例B再次读取
5. 验证本地缓存同步

**预期结果**:
- 各实例读取到相同的缓存值
- 缓存删除操作广播到所有实例
- 本地缓存与Redis保持一致
- 使用Redis Pub/Sub或消息队列同步
- 同步延迟<100ms

### TC-ARC-006: 缓存降级策略

| 属性 | 内容 |
|------|------|
| **用例ID** | TC-ARC-006 |
| **用例名称** | 缓存降级策略测试 |
| **前置条件** | 1. Redis服务可模拟故障<br>2. 降级策略已配置 |
| **优先级** | P0 |
| **所属需求** | ARC-AVA-001 |

**测试步骤**:
1. 正常访问使用缓存
2. 模拟Redis连接超时
3. 观察系统降级行为
4. 直接访问数据库
5. 恢复Redis服务

**预期结果**:
- Redis故障时自动降级
- 直接访问数据库，服务不中断
- 记录降级日志
- Redis恢复后自动切换回缓存模式
- 熔断器防止数据库过载
